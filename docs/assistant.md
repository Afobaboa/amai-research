# ИИ-помощник: Cloud.ru и DeepSeek

Справа в рабочем интерфейсе LIMS доступен чат для обсуждения экспериментов, гипотез и работы с сайтом. Модель подключается через Cloud.ru Foundation Models. Без API-ключа остальное приложение работает, а панель показывает, что подключение ещё не настроено. Импорт Excel по-прежнему не выполняется: помощник читает записи текущей базы LIMS, включая учебные записи в деморежиме.

Ответ появляется в панели постепенно, по мере получения текста от Cloud.ru. Во время ожидания показаны анимированные статусы: «Думаю…», «Смотрю эксперименты…», «Изучаю результаты и статистику…», «Изучаю рецептуры…» и другие. Они меняются по фактически запущенным серверным инструментам. Уже напечатанный открытый текст сохраняется при переходе к следующему этапу и остаётся над итоговым ответом; завершённый ответ вместе с этими пояснениями восстанавливается после обновления страницы. Внутренние рассуждения модели не передаются в браузер. При остановке или обрыве частичный ответ помечается как незавершённый и не становится частью отправляемой истории; запрос можно повторить.

Браузер запрашивает `POST /assistant/chat/` с `Accept: text/event-stream`. Сервер отправляет SSE-события `status`, `delta`, `done` или `error`; `done` содержит окончательный текст и источники. Служебные события `ping` поддерживают поток при получении скрытых рассуждений или сигналов активности провайдера и не содержат текста модели. Если модель сначала написала вступление, а затем вызвала инструмент, `status` с `reset: true` завершает текущий текстовый фрагмент и начинает следующий, сохраняя предыдущий в панели. Эти промежуточные фрагменты хранятся в браузере в поле `progress` сообщения помощника; в контекст следующего запроса уходит только окончательный ответ. Запросы без SSE продолжают получать прежний JSON-ответ. Поток имеет ограничения времени и размера; незавершённый поток не считается успешным ответом. Для прокси выставлены `X-Accel-Buffering: no` и `Cache-Control: no-transform`.

Таблицы в ответах отображаются с заголовками и горизонтальной прокруткой, если не помещаются в окно. На компьютере и планшете ширину окна можно менять, потянув за левую границу; выбранная ширина сохраняется при переходах между страницами в текущей вкладке. Граница также доступна с клавиатуры: ←/→ меняют ширину, Shift ускоряет изменение, Home/End выбирают минимальную/максимальную ширину. На телефоне чат занимает всю ширину экрана.

С каждым вопросом помощник получает адрес текущей страницы и снимок её форм: подписи и значения полей, названия выбранных вариантов, разделы и строки состава, отметки об изменении полей. Снимок включает ещё не сохранённый ввод и обновляется при повторе запроса. Помощник учитывает его как текущий черновик, отдельно от сохранённых данных карточки в БД. На страницах списков он также видит введённые фильтры. Большие формы ограничиваются 200 полями и 24 000 символами JSON; сокращение явно отмечается в контексте.

Снимок отправляется только вместе с вопросом; набор текста сам по себе не вызывает запросов к модели. Пароли, служебные и скрытые поля, CSRF-токены и содержимое файлов исключены. Снимки форм не записываются в историю чата в браузере и не сохраняют изменения формы в БД.

## Как получить ключ

В личном кабинете Cloud.ru:

1. Убедитесь, что в AI Factory доступен сервис Foundation Models.
2. В разделе «Пользователи → Сервисные аккаунты» создайте аккаунт уровня проекта или откройте существующий.
3. Откройте «Учётные данные доступа → Создать API-ключ» и выберите сервис **Foundation Models**. Задайте срок действия и при необходимости ограничения ключа.
4. Сохраните показанный **Key Secret**: после закрытия окна его нельзя посмотреть повторно. В LIMS нужен именно этот секрет, а не Key ID.

Это порядок из [официального быстрого старта Cloud.ru](https://cloud.ru/docs/foundation-models/ug/topics/quickstart). Отдельный ключ DeepSeek или OpenAI для этого подключения не требуется.

По умолчанию указана модель `deepseek-ai/DeepSeek-V4-Pro`. В [официальной таблице Cloud.ru](https://cloud.ru/docs/foundation-models/ug/topics/overview__available__models), проверенной 01.11.2026, она отмечена как внутренняя модель с Function Calling и Reasoning. Для агентного доступа к данным выбирайте модель с **Function Calling**; точный ID и доступность для вашего аккаунта проверяйте по API. При выборе внешней модели учитывайте указанное Cloud.ru размещение: запросы к ней передаются внешнему провайдеру.

## Куда записать ключ при локальном запуске

Создайте или отредактируйте файл **`LIMS/.env`** рядом с `manage.py`. Если файл уже есть, добавьте параметры к существующим, сохранив остальные значения:

```dotenv
CLOUD_RU_API_KEY='вставьте_сюда_Key_Secret'
CLOUD_RU_MODEL=deepseek-ai/DeepSeek-V4-Pro
CLOUD_RU_BASE_URL=https://foundation-models.api.cloud.ru/v1
CLOUD_RU_TIMEOUT=90
ASSISTANT_MAX_TOOL_ROUNDS=5
```

Остановите dev-сервер и снова выполните из каталога `LIMS`:

```bash
make dev
```

Без `make`: `python3 scripts/local.py dev`. После входа и выбора сотрудника откройте помощника справа. Если меняли `.env`, нужен именно перезапуск процесса сервера.

Локальный запуск читает из `.env` только перечисленные настройки помощника. Настройки production-БД, домена и пароля из этого файла не меняют локальный профиль `config.local`. Явно заданные переменные окружения имеют приоритет над файлом. Значения в `.env` не исполняются как shell-код и не интерполируются: используйте сам секрет, а не `${OTHER_VARIABLE}`.

Посмотреть доступные модели, не выводя ключ:

```bash
python3 scripts/local.py manage assistant_models
```

Команда обращается к `GET https://foundation-models.api.cloud.ru/v1/models`. Скопируйте нужный ID целиком в `CLOUD_RU_MODEL`, затем перезапустите сервер. Структура запросов описана в [спецификации API Cloud.ru](https://cloud.ru/docs/foundation-models/ug/topics/api-ref__specs).

## Настройка Docker Compose

Добавьте те же пять параметров в `LIMS/.env` на сервере. Compose передаёт их только контейнеру `web`. После обновления исходников и настроек:

```bash
docker compose config --quiet
docker compose up -d --build web
```

Для проверки доступа и списка моделей:

```bash
docker compose exec web python manage.py assistant_models
```

Остальные параметры production-развёртывания описаны в [README](../README.md#подготовка-облачного-запуска). Чат использует существующее соединение Django с БД; дополнительный пароль базы для модели не нужен.

## Что доступно агенту

Агент получает инструменты поиска и чтения, которые выполняются на сервере:

- **Данные лаборатории:** материалы, партии, типы смесей, версии рецептур с составом и планом заправки, карточки испытаний с условиями, результатами и наблюдениями, показатели, первичные фрагменты источников, шаблоны и сохранённые расчёты. Поиск поддерживает фильтры по материалу, рецептуре, показателю и числовому диапазону; возвращает количество, страницы записей и ссылки на карточки.
- **Сайт:** действующие HTML-шаблоны, CSS/JavaScript интерфейса, маршруты и разрешённые Markdown-документы проекта. Агент может найти нужный файл и прочитать строки, чтобы объяснить реальную форму или путь по сайту.

Перед выводами о лабораторных данных системные инструкции требуют искать факты в БД, читать связанные карточки, приводить ссылки и различать наблюдение, расчёт и гипотезу. Неподтверждённая связь рецептуры с испытанием не доказывает фактический состав; отсутствие значения не считается нулём. Результат исследования следует проверять по указанным карточкам и первоисточникам.

Инструменты работают **только на чтение**: модель не выполняет SQL, Python или команды и не создаёт/редактирует рецептуры и испытания. Доступ к файлам ограничен серверным списком; `.env`, настройки приложения, служебные сессии, учётные данные и произвольные файлы недоступны. Вложения не распознаются и не читаются как произвольные файлы; агент видит сохранённые в БД сведения об источниках и первичные фрагменты.

Сообщение пользователя, необходимая история диалога, снимок текущих форм и выбранные инструментами данные/фрагменты кода отправляются через Cloud.ru API. В браузер API-ключ не передаётся. Доступ к чату требует той же сессии входа и активного профиля сотрудника, что и просмотр LIMS; он доступен авторам и читателям. POST защищён CSRF.

История чата хранится в `sessionStorage` текущей вкладки с привязкой к сотруднику и переживает переходы между страницами; сохраняется до 16 последних сообщений, а отправляемая история ограничена 48 000 символами. При превышении лимита старые пары вопрос/ответ удаляются. Новый диалог и выход из системы очищают историю. Чат не создаёт постоянный журнал бесед в базе LIMS. Во время ответа можно набирать следующий вопрос; черновик сохраняется после завершения или остановки ответа. Отправка следующего вопроса доступна после завершения текущего. Кнопка ■ и клавиша Esc останавливают текущий ответ, оставляя чат открытым. Когда ответа нет, Esc сворачивает чат. Остановка прекращает ожидание в браузере; уже отправленный провайдеру запрос может завершиться и тарифицироваться.

Для повторного ввода браузер отдельно хранит последние 25 отправленных вопросов в `localStorage` с привязкой к сотруднику. В пустом поле ↑ выбирает последний вопрос; дальнейшие ↑/↓ переключают вопросы от новых к старым и обратно. Стрелка ↓ после самого нового вопроса возвращает пустое поле. Редактирование выбранного вопроса завершает просмотр истории, и стрелки снова перемещают курсор по тексту. Сочетание указано в подсказке под полем ввода. История вопросов сохраняется после обновления страницы и начала нового диалога; кнопка «Повторить запрос» не добавляет ещё одну запись. Вызов вопроса из истории сам по себе не отправляет его модели.

## Ограничения и диагностика

`CLOUD_RU_TIMEOUT` ограничивает ожидание отдельного API-запроса; сервер дополнительно ограничивает общую длительность ответа и число раундов инструментов (`ASSISTANT_MAX_TOOL_ROUNDS`). Поиск и вложенные списки имеют предел размера и явно отмечают сокращение: агент должен уточнять запрос или переходить к следующей странице, а не считать первую выборку полной базой. Чат не строит обучающие модели и не импортирует архив.

Если чат не подключается:

- **Не настроен:** проверьте имя `CLOUD_RU_API_KEY`, расположение `LIMS/.env` и перезапуск сервера/контейнера.
- **Ошибка авторизации:** проверьте Key Secret, статус и срок действия ключа, выбранный сервис Foundation Models, ограничения ключа и доступ аккаунта.
- **Модель недоступна или не поддерживает инструменты:** выполните `assistant_models` и выберите точный ID модели с Function Calling.
- **Лимит или квота:** проверьте баланс, квоты и ограничения частоты в Cloud.ru.
- **Тайм-аут:** повторите более узкий запрос; проверьте сетевой доступ сервера к Cloud.ru.
- **Нужно снова войти:** обновите страницу, войдите и выберите активного сотрудника.

`.env` исключён из Git и Docker build context. Не записывайте секрет в шаблоны, JavaScript, документацию или сообщения чата. При утечке замените ключ в Cloud.ru и обновите серверную настройку.

Автоматические тесты используют подменённые ответы API и временную БД. Локальный runner не загружает API-ключ из `.env` и удаляет унаследованные настройки помощника для тестов, миграций и обычных проверок. Реальное подключение к Cloud.ru требует вашего ключа и выполняется после его настройки; без него работа с выбранной моделью и её ответы не проверены.
