# AMAI UI

Создавай рабочие интерфейсы в узнаваемом стиле AMAI Tech. Пакет оформляет интерфейс; он не задаёт производственные формулы, авторизацию или бизнес-процессы.

## Ресурсы

- [amai-theme.css](amai-theme.css) — канонические токены.
- [amai-components.css](amai-components.css) — компоненты с префиксом `amai-` и базовые правила внутри `.amai-ui`.
- [index.html](index.html) — семантическая разметка и примеры состояний.
- [demo.js](demo.js) — примеры взаимодействия (вкладки, native dialog, валидация); это не backend и не хранилище.
- [README.md](README.md) — подключение, адаптация к React/Vue, происхождение и ограничения.

При разработке сначала изучи тему и нужные компоненты. Не подменяй реализацию проекта всей демонстрационной страницей. Сохраняй существующий framework, маршруты и обработчики.

## Визуальные решения

- Белая поверхность карточек на светлом серо-голубом фоне `--amai-bg`. Тёмно-синяя навигация `--amai-navy`, тёмный основной текст `--amai-ink`.
- Яркий синий `--amai-brand` — графика и брендовый акцент. Более тёмный `--amai-primary` — кнопки с белым текстом, ссылки и активные действия. Не заменяй его ярким акцентом без проверки контраста.
- Шрифт Inter, если он уже подключён в проекте; иначе системный стек из темы. Шрифты в пакете не вложены. Не добавляй внешний CDN ради демонстрации.
- Базовый текст 16 px, подписи 14 px. Большие числовые показатели с tabular-nums; короткие заголовки. Сохраняй единицы измерения и русское форматирование чисел.
- Отступы по шкале 4/8/12/16/24/32/48 px. Радиусы: 8 px для полей и кнопок, 12 px для карточек, 20 px для диалогов. Тени слабые, без декоративного свечения.
- Один визуально основной вызов к действию в контексте. Зелёный, янтарный и красный обозначают состояния, всегда сопровождаются текстом.
- Графики используют `--amai-chart-*`, текстовую легенду, единицы и доступную детализацию. Не кодируй смысл только цветом; подсказки должны быть доступны с клавиатуры и касанием. Пакет не содержит готового графического движка.

## Подключение и поведение

1. Скопируй два CSS-файла в ассеты проекта, подключи тему перед компонентами. Добавь `amai-ui` корневому контейнеру; модальные порталы тоже должны находиться внутри такого контейнера.
2. Классы `amai-btn`, `amai-card`, `amai-field`, `amai-input`, `amai-tabs`, `amai-table`, `amai-dialog` показывают базовую форму. Для локальных изменений добавляй классы проекта и переопределяй токены, не редактируя глобальные стили других экранов.
3. На десктопе допустима боковая навигация. На небольших экранах она перестраивается; не скрывай ключевые действия. Таблицу можно прокручивать внутри контейнера, длинные пояснения оставляй читаемыми или предложи список.
4. Для планшета используй `data-density="touch"` на `.amai-ui`; минимальная высота действий 52 px. Обычная высота 44 px. Не делай hover единственным способом выполнения действия.
5. У полей должны быть label, объяснение ошибки и связь через aria-describedby. Вкладки: aria-selected, roving tabindex, стрелки/Home/End. Диалог: доступное название, фокус внутри, Escape и возврат фокуса. По возможности используй нативные элементы.
6. Для каждого реального потока учти загрузку, отсутствие данных, ошибку с повтором и успешное завершение. Не показывай фиктивное «сохранено» до ответа приложения. Уведомления через live-region; критические ошибки остаются видимыми.
7. Пользовательский текст выводи безопасно (textContent / штатное экранирование framework). Проверка формы на клиенте не заменяет проверку сервером.

## Язык и границы

Пиши короткие русские подписи по задаче пользователя: «Сохранить», «Повторить», «Выполненная работа». Без «прототипа», внутренних версий, объяснения API и формул в рабочих экранах, если пользователь их не запросил. В библиотеке и обучающем демо маркировка примеров допустима.

Не переносить в новые продукты названия Троль Авто, реальные ФИО, производственные данные, адреса серверов, ключи или формулы эффективности из проектов-источников. Не применять новые стили к действующим системам и не развёртывать их без задачи на такое изменение. Словесная надпись AMAI в демо не заменяет официальный файл логотипа.

## Проверка результата

Проверь реальные сценарии, а не только снимок: ввод/ошибка/сохранение, клавиатура, закрытие диалога, возврат фокуса. Посмотри экран на широком десктопе, планшете и телефоне, включая длинный текст. Проверь отсутствие горизонтального скролла всей страницы, контраст текста и элементов, prefers-reduced-motion. Покажи результат и честно укажи непроверенные ограничения. Не заявляй соответствие всей WCAG по одной проверке цветов.
